Responsible-AI mechanisms
Prompt injection: bounded user text is passed in user-role content. Server-created system instructions and canonical conversation roles are not accepted from the client. Model preference extraction is strict-schema validated; server derives readiness. The saved itinerary accepts only allowed activity IDs and catalogue hotel IDs, rejecting arbitrary factual prose and fields. Chat prose still relies on model adherence and needs real adversarial evaluation; no universal injection immunity is claimed.
Hallucination: fixed versioned catalogue; no model-authored property names/evidence/prices. Empty inventory yields zero hotels and null costs. Server checks exact dates and eligible IDs. Source labels include Guest-verified, Hotel-claimed and Unverified; adverse evidence is distinct from supportive evidence. Guest verification is never a current guarantee. Generic activity suggestions are clearly labelled as such.
Popularity bias: no click/sales/popularity ranking features are collected or used. Catalogue eligibility depends on destination and relevant constraints.
Price bias: expensive properties are not considered inherently better. Missing prices remain unknown; they fail affordability. No incomplete sum is represented as a complete trip total.
Geographical bias: destination is preserved, including unsupported international places. Gaps are shown explicitly. Expanding coverage requires actual independent research, never substitution with a popular city.
Review bias: claim-level source dates/substance are used, not review counts or rating volume. Adverse lift/step-free evidence is filtered for no-stairs needs; unrelated adverse claims remain visible. Unknown evidence never becomes supportive.
