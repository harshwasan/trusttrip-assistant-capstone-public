SECURITY AND RATE-LIMIT PASS — 8 October 2026
Findings and fixes:
- Non-AI routes had no request limits. Draft save, reset, trip listing, trip reads, review and account routes each run Firestore reads, writes or transactions, so a script could exhaust the free Firestore quota and take the app down. The unauthenticated /api/config and the token check had no cap either. Added server/ratelimit.js (no new dependency):
  - every /api request: 120 per minute per IP;
  - POST /api/chat and POST /api/trips: 12 per minute per IP;
  - each verified user: 60 reads and 20 writes per minute.
  A blocked request gets 429 with Retry-After. Static pages are not limited. Each limit is configurable (RATE_LIMIT_* in .env.example).
- Per-user AI limits could be multiplied by creating more free accounts, letting one person use up the 200-per-day global AI cap for everyone. The per-IP AI limit now bounds this per client. Firebase email verification or App Check would strengthen it further (not implemented).
- AUTOMATION_TOKEN had no minimum length. Automation now stays disabled unless the token has at least 32 characters, so a short guessable token cannot be used.
- TRUST_PROXY (proxy hop count, default 0) controls how the client IP is read. Behind AI Studio or Cloud Run hosting set TRUST_PROXY=1; with 0 behind a proxy, every user shares the proxy's IP and therefore one per-IP budget.
- Limits are held in memory per server instance and reset on restart. With several instances the effective limit multiplies. The durable Firestore AI counters in usage.js are unchanged and remain the cost control for Gemini.

Checked and found sound: Firestore rules deny all client access; every private route verifies the Firebase ID token with revocation checking; trip reads check ownership; reviewer access needs a server-assigned custom claim; the automation token is compared in constant time; request bodies are capped at 24 KB and validated with strict schemas; React escapes all rendered text, and no raw-HTML rendering is used; AI output is accepted only as catalogue IDs validated on the server.

Still open: a Content-Security-Policy (including frame-ancestors, since X-Frame-Options was removed for the AI Studio preview); dependency advisories inside the Firebase SDKs (not reachable, see above); no pagination on GET /api/trips (bounded in practice by the 5-itineraries-per-day limit).

Verification: 73/73 automated tests pass, including new rate-limit and token-length tests. A live HTTP check returned 429 with Retry-After: 60 on the fourth request at a limit of 3, and the page itself still served 200.
